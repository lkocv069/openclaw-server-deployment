# OpenClaw服务器部署：选对机房和配置，2核4G起步，装完直接连飞书和QQ

OpenClaw（也就是之前的 Clawdbot、Moltbot）装在本地电脑上和装在云服务器上，是两种体验。本地跑，合上笔记本它就停了；而且它本身要读文件、执行命令、调模型接口，权限给少了干不了活，给多了又很难放心。把它放到服务器上，这两件事一起解决：7×24 在线，你从手机或电脑连过去下指令，工作数据留在云端，跟本机的私人目录隔开。

下面这套流程按实际部署顺序走：先定机房和配置，再开机装服务，然后是远程访问和聊天渠道，最后是成本和容易踩的坑。

## 一、部署前先定三件事

**1. 机房放哪**

OpenClaw 本身不产生算力压力，它的负载几乎全在“调模型 API”和“跑命令”上。所以你选的节点，第一标准是到模型接口的网络质量：

- 用 Anthropic、OpenAI、OpenRouter 这类海外接口：香港、美国、日本、韩国、德国节点更稳，回程线路好的话延迟低、掉线少。
- 只用国内模型（通义千问、DeepSeek、Kimi 等）：国内节点延迟更低，成本也更低。

**2. 配置要多少**

三个不同来源的说法可以放在一起看：OpenClaw 官方 Docker 文档要求容器至少 2GB 内存；阿里云 ECS 文档建议 4 核 4GB 及以上，共享型实例还要再往上选；雨云社区那份 OpenClaw 部署教程给的建议是 2 核 4G。

合起来就是：**2核2G 能把基础任务跑通，2核4G 是舒服的起点，同时跑多个任务或者频繁调用工具就往 4核8G 走。**磁盘不是瓶颈，但尽量选 SSD，因为状态库和缓存都在本地盘上。

**3. 系统选什么**

Debian 或 Ubuntu 最省事，官方文档和社区教程基本都按这两条线写。别用 Windows Server——Gateway 需要桌面登录后才启动，放在服务器上属于自己给自己找麻烦。

## 三、从开机到 OpenClaw 跑起来

按顺序走，中途别关页面。

1. **下单**：节点按上面的标准选，配置选 2核4G，系统选 Debian 12/13，预装软件勾 OpenClaw 或 1Panel。
2. **记下三个信息**：公网 IP、root 密码、控制台入口。这三样之后每次都要用。
3. **登录服务器**：本地终端 `ssh root@你的公网IP`，或者用雨云控制台自带的连接方式。
4. **如果没预装**，走官方安装脚本或 Docker Compose。用 Docker 的话注意两点：容器给够 2GB 内存；`~/.openclaw`（配置和状态）和 workspace 目录都要挂载出来，不然容器一重建数据就没了。
5. **跑配置向导**：`openclaw onboard --install-daemon`。模型那一项选你实际在用的供应商，填 API Key。国内用户接飞书或 QQ 相对省事，走 Telegram 也可以。
6. **授权你的设备**：第一次用浏览器访问时会提示有设备待批准，在服务器上执行 `openclaw devices list` 拿到 requestId，再执行 `openclaw devices approve <requestId>`。这一步是安全机制，不是报错，换设备访问时都要做一次。
7. **验证**：WebUI 里发一条消息，能正常回复就算通了。服务端也可以直接查 `http://127.0.0.1:18789/healthz`，返回正常说明网关进程活着。

已经装过的版本升级后如果行为异常，`openclaw doctor --fix --non-interactive` 可以先跑一遍再做别的判断。

## 四、WebUI 怎么访问才算安全

OpenClaw 的 Gateway 默认只监听 `127.0.0.1:18789`，也就是只有服务器本机能访问。这是官方给的默认值，别急着改。想远程用界面的两种做法：

**SSH 隧道（推荐）**

bash
ssh -L 18789:127.0.0.1:18789 root@你的服务器IP


然后在本地浏览器打开 `http://localhost:18789`。流量全程走 SSH，公网上没有暴露端口。

**改成 lan 绑定**

bash
openclaw config set gateway.bind lan
openclaw gateway restart


改完 Gateway 会监听所有网卡。这时候必须在雨云控制台的安全组里放行 TCP 18789，**并且把来源限制成你自己的出口 IP，不要开 0.0.0.0/0**。另外官方说明写得很清楚：绑定到 lan 或 tailnet 时，要么配好 `gateway.auth.token` / `gateway.auth.password`，要么把认证交给可信的代理层。

## 五、把聊天渠道接上

OpenClaw 支持飞书、企业微信、钉钉、QQ、Telegram、Discord、WhatsApp 等渠道，配置方式基本是“在对应平台建应用 → 拿到 App ID / Secret 之类的凭证 → 填进 OpenClaw 配置”。

几个实际会遇到的情况：

- 微信渠道目前主要走手机端，PC 端还不完整。
- 用 1Panel 面板部署的话，渠道是在面板的智能体配置里点选的，扫码或填凭证都可视化，新手选这条路能少看很多日志。
- 如果打算一个机器人给整个团队用，官方给的边界是：所有用户处在同一信任范围、且只用于业务。运行环境要独立，不要在上面登个人 Apple/Google 账号，也不要挂个人的浏览器或密码管理器配置。成员之间互相不信任，就按网关或系统用户拆开部署。

## 六、小内存机器启动慢，可以这样调

2核4G 跑得动，但低配 VM（尤其是 ARM 机器）执行 CLI 命令时可能有明显卡顿。官方文档给的调优方式是开启 Node 的模块编译缓存：

bash
grep -q 'NODE_COMPILE_CACHE=/var/tmp/openclaw-compile-cache' ~/.bashrc || cat >> ~/.bashrc <<'EOF'
export NODE_COMPILE_CACHE=/var/tmp/openclaw-compile-cache
mkdir -p /var/tmp/openclaw-compile-cache
export OPENCLAW_NO_RESPAWN=1
EOF
source ~/.bashrc


第一次执行命令时会把缓存预热，之后的启动会快一些。用 systemd 管理服务的话，再把 `Restart=always`、`RestartSec=2`、`TimeoutStartSec=90` 配上，同时把 `OPENCLAW_NO_RESPAWN` 和 `NODE_COMPILE_CACHE` 写进服务环境变量，重启行为会更可控。

如果你打算从源码编译（需要 Node.js 22.22.3+、24.15+ 或 25.9+），那配置就别压到 2核了，编译过程本身就要吃资源。

## 九、安装过程中最容易卡住的几个点

**端口 18789 被占用。**先确认是不是之前装过一版还在跑：

bash
netstat -tlnp | grep 18789


**API Key 无效。**绝大多数“装完了但发消息不回复”都是这个原因：供应商选错、Key 已过期、或者 Base URL 和 Key 的地区不匹配（国内站和海外站的 Key 不能混用）。

**权限给太大。**OpenClaw 要读文件、执行命令、装插件，这些能力叠在一起意味着一次误判就能造成实际损失。能容器化就容器化，按最小权限原则来，别把长期有效的密钥直接写进配置里，也不要把管理端口直接暴露在公网。

**它读外部内容时的提示词注入。**它抓网页、读文件的时候，那些内容里可能藏着诱导性指令，导致它执行预期之外的操作。这是这类智能体的固有风险，不是某个平台的 bug，所以重要操作不要全自动放权。

**忘了备份。**服务器上的 state 和 workspace 才是真正的资产，模型接口随时能换回来，会话记录和文件丢了就没了。定期备份这两块目录。
